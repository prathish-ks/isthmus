# ADR-036: v2026.10.0 Pin Promotion — Closing Review

Status: accepted, 2026-10-11. Closes the v2026.10.0 promotion in full —
the pin move (Steps 0-9) and the Step 10 retrospective both — the same
way `ADR-035-v2.4.0-pin-promotion-closure.md` closed the v2.4.0 one: a
single dated review recording that the pin move itself is correct and
fully gated, superseding ADR-035 as the current closing review, plus the
playbook's own required retrospective against `docs/design-laws.md`
(`docs/promotion-v2026.10.0.md`, [PR #73](https://github.com/prathish-ks/isthmus/pull/73),
[PR #76](https://github.com/prathish-ks/isthmus/pull/76)).

## Context

This project's stable baseline (`docs/baseline.md`, `docs/
upstream-pin.json`) was pinned to nanocoai/nanoclaw `v2.4.0` (commit
`143db6c9`, released 2026-09-23) since ADR-035 closed that promotion.
`docs/promotion-v2026.10.0.md` is the living plan for moving that pin to
`v2026.10.0` (commit `7203e00d`, released 2026-10-09) — a much larger
range than the v2.4.0 promotion covered: **91 commits, 83 unique PRs**,
75 of them classified and implemented pre-tag across 17 batches
(`docs/promotion-prep-notes.md`), the remaining 8 reviewed and ported in
this promotion's own "7-PR tail."

The plan organized this work into two PRs plus this closing step, per
its own "PR boundaries" section:

1. **Implementation** (Steps 0-3, the 7-PR tail, the file inventory) —
   [PR #73](https://github.com/prathish-ks/isthmus/pull/73), merged
   (`9a195c5f`).
2. **Follow-ups** (the three "must close or accept-and-document" items
   fixed outright, Step 7's live migration-continuity test, and two
   rounds of independent/external security review findings) —
   [PR #76](https://github.com/prathish-ks/isthmus/pull/76), merged
   (`08639454`).
3. **This step**: the final, isolated pin-move — `docs/upstream-pin.json`,
   `docs/baseline.md`'s Stable Baseline section, this closing ADR, and the
   filled-in evidence index — no implementation changes, so that "is the
   pin move itself correct and fully gated" is reviewable on its own.

## What this review confirms

Everything here was checked directly against the live state — the actual
GitHub check-runs API, the actual live upstream tag and `upstream/main`
HEAD, the actual merged PRs — not assumed from a document's own
self-report, the same discipline ADR-035 established.

**Both PRs are merged with real CI evidence.** PR #73's final commit
(`dfee5d21`) and PR #76's final commit (`367ee4dd`) each show their `ci`
required-gate check run concluded `success` on GitHub Actions, verified
via `GET /repos/prathish-ks/isthmus/commits/<sha>/check-runs` directly —
`wiring-registry-check`, `go-host`, and `performance-gate` all green on
both.

**The tag is immutable and hasn't drifted since planning began.**
`v2026.10.0` still resolves to
`7203e00dc271cc2ea9ea84bb130731b8ca00319e` — re-verified live
(`GET /repos/nanocoai/nanoclaw/git/refs/tags/v2026.10.0` → tag object
`36092f68` → target commit) immediately before this pin move, matching
the SHA `docs/promotion-v2026.10.0.md` captured at Step 0 exactly.

**`upstream/main` has moved further than Step 0/Step 8 last recorded —
checked honestly, not quietly reconciled.** The promotion doc's Step 8
re-validation (done 2026-10-10) found `upstream/main` one trivial commit
ahead of the tag (`#4066`, a dependency bump). Re-checked live for this
closing review: `upstream/main` is now **4 commits / 2 PRs** ahead
(`#4066`, already known, plus `#4069` — a Claude Code/Agent SDK/Codex
version-pin bump, merged 2026-10-10, after this promotion's own Step 8
check). Both are **past the `v2026.10.0` tag commit itself** — by
definition outside this promotion's scope, the same way `#4066` alone
was already excluded. This changes nothing about what's being pinned;
it is exactly the kind of drift `docs/upstream-pin.json`'s own
`last_reviewed_upstream_main_commit` field exists to track for the
*next* promotion's Step 0, not something to silently absorb into this
one. Recorded in `docs/upstream-watch-log.md`'s new entry, and
`last_reviewed_upstream_main_commit` is updated to `upstream/main`'s
current HEAD (`a0c79dd8`) in this same commit.

**Step 1 (consumed-contracts re-check) — done, one break, closed.** All
8 rows of `go-host/docs/version-compatibility.md` §1 walked against the
real diff: 7 clean, 1 broke (`#4061`'s CLI-restart guard falsy-value
scope bypass) and closed in both `src/cli/guard.ts` and the Go kernel's
`DecideRestartLike` in the same commit (`630f48c5`) — a genuine
consumed-contract break, fixed, not deferred.

**Step 2 (full-diff file-inventory CSV) — done, zero unclassified.**
`docs/promotion-v2026.10.0-file-inventory.csv` — 253 rows across the
whole repo (not scoped to `src/` alone), every row bucketed (61 A / 112 B
/ 80 C) and carrying a `reconciliation_decision`. Per-file fidelity
checked against `git ls-tree -r HEAD`, not inherited blindly from each
PR's top-level classification — this caught real per-file mismatches
(detailed in the promotion doc's Step 2 section) that a PR-level label
alone would have missed.

**Step 3 (Bucket B trace) — done, zero acceptance records needed.**
Every Bucket B finding in this range resolved to either closed outright
(`#4061`'s bypass plus an independently-found Telegram `@botname`
admin-gate bypass, `#4060`'s Mattermost shell-injection, `#4059`'s
OneCLI-installer MITM-downgrade) or named-and-deferred (never a silent
accepted exception) — matching ADR-035's own precedent of zero accepted
bypasses for this fork.

**The three "must close or accept-and-document" items — all fixed, not
accepted.**
- `#3908` — A2A failure-notice reply-loop suppression. A `failureNotice`
  marker checked before every outbound write that could answer a notice
  with another, container-side only, matching upstream's real shipped
  shape (`FAILURE_NOTICE_FIELD`, `failureNoticeWake`,
  `sendsFailureNotice`).
- `#4039` — OneCLI upgrade guide now refuses to run with `ONECLI_VERSION`
  unset or inconsistently re-stated — closed in two passes: the initial
  `: "${ONECLI_VERSION:?...}"` guard, then a correction (external
  review, PR #76) that found the guard checked one variable while the
  actual `docker compose` commands re-stated the placeholder
  independently — fixed by assigning the variable once, guarding that
  same variable, and exporting it for Compose's own interpolation to
  consume.
- `#3966` — Iron Proxy keyless local HTTP model support. Took three
  passes to close correctly, each one found by a different review:
  1. Initial port: a new `modelAuthorities` provider-contract field,
     `iron-proxy-local-model.ts`'s origin filtering, and a narrow Go
     admission rule (plain HTTP, no CONNECT tunnel, non-default port, no
     collision with Iron's own ports, OpenAI-shaped route).
  2. An independent code review (this project's own `code-review` skill)
     found the self-SSRF exclusion was computed in TypeScript but never
     reached the Go proxy — `forward()` had zero knowledge of Iron's own
     configured ports — plus a string-vs-numeric port-80 comparison bug
     letting a zero-padded `"080"` slip past both layers. Both fixed:
     `forward()` now derives refused ports straight from its own
     `Listen`/`ApprovalTarget` config.
  3. An external PR review correctly identified that step 2's own fix
     still didn't enforce *which* ports were legitimately declared — Go
     admitted any non-default, non-self port, not just ones a provider
     actually declared via `modelAuthorities`. Closed by threading
     `local_model_ports` from `ironFrontConfig()` into `main.go`'s
     config and enforcing it in `forward()` before the approval bridge
     is ever reached — the real, primary admission gate, with the
     TypeScript bridge's origin-consistency check now an explicit
     second layer behind it, not the only one.
- `#3948` — gateway survival through update cutover/rollback.
  `drainContainers`'s missing gateway-role exclusion fixed (mirroring
  `reapResidue`'s own pattern) and proven with a **live** Iron Proxy
  cutover/rollback test (`docs/promotion-v2026.10.0-rollback-iron-proxy.md`),
  not just the architectural read an earlier review flagged as
  insufficient. That live test caught a second real bug in the fix's
  first attempt (`docker ps -q`/`--format` is an invalid combination —
  Docker silently drops `--format` and the role read back `undefined`),
  which mocked unit tests could not have caught, and a third: the
  gateway-filter and container-list parsing logic was duplicated,
  untested-as-one-unit, across `drainContainers` and `reapResidue` —
  extracted to a shared `parseNonGatewayRows` in `src/drivers/types.ts`.

**Step 6 (testing/docs/CI, including the ADR-028 wiring-registry check)
— done, genuinely run, not assumed.** The promotion doc had flagged this
specifically as "still needs a real run." Run as part of this closing
review: `pnpm exec tsx scripts/check-wiring-registry.ts` → `13 entries
OK`. No new entry was added — ADR-028's own scope is deliberately narrow
(LAW-05: "found by one of these [2026-09-24] audits or a successor, not
merely seemed prudent"), and while this promotion's own independent
review found and closed a real wiring-loss-shaped gap in `#3966`'s local-
model admission path (a security property that existed only as a
TypeScript-side side effect with nothing in Go actually enforcing it),
that class of finding was closed at the code level (Step 3 above), not
promoted into a new standing registry entry outside the audits ADR-028
names.

**Step 7 (migration continuity) — done, with real evidence, not an
architectural read.** `docs/promotion-v2026.10.0-rollback-iron-proxy.md`:
a real git clone at the outgoing pinned tag, a real running Iron Proxy
gateway container, the real `prepareUpdate → validateUpdate →
cutoverUpdate → rollbackUpdate` state machine driven end to end —
including a genuine Docker Desktop storage fault that interrupted the
cutover mid-flight, recovered cleanly via `rollbackUpdate` with no data
loss and the gateway container's identity unchanged throughout.

## Decision

**Promote the pin from v2.4.0 to v2026.10.0.** `docs/upstream-pin.json`
and `docs/baseline.md`'s Stable Baseline section are updated in the same
commit as this ADR, per LAW-09's own discipline. Every line of `docs/
promotion-v2026.10.0.md`'s "Open before Step 8/9" checklist is checked
as of this review; the evidence index below is this pin move's own
record.

**Process decision, going forward, same as ADR-035's and ADR-017's
before it:** the automated half (`upstream-watch`'s daily job, `.github/
workflows/ci.yml`'s `cron: "0 13 * * *"`, noticing a new tagged release
exists) stays automated; the qualitative half
(reading what changed, deciding whether it touches this project's ported
surface) stays a human-directed step. `docs/upstream-watch-log.md`'s
incremental Watch mode — used for the first time this promotion cycle —
is a genuine improvement over starting Step 0 cold; keep running it
between promotions rather than letting the log go stale again.
