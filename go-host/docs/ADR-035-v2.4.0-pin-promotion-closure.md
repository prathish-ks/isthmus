# ADR-035: v2.4.0 Pin Promotion — Closing Review

Status: accepted, 2026-09-27. Closes the v2.4.0 promotion (`docs/
promotion-v2.4.0.md`, [PR #50](https://github.com/prathish-ks/isthmus/pull/50))
the same way `ADR-017-p9-07-upstream-overlap-review.md` closed the v2.3.0
one — a single dated review recording that the pin move itself is
correct and fully gated, superseding ADR-017 as the current closing
review. F6's own row in the promotion plan named this ADR's job; this is
that ADR.

## Context

This project's stable baseline (`docs/baseline.md`, `docs/
upstream-pin.json`) was pinned to nanocoai/nanoclaw `v2.3.0` (commit
`54d9d9a5`, released 2026-08-24) since Phase 0. `docs/promotion-v2.4.0.md`
is the living plan for moving that pin to `v2.4.0` (commit `143db6c9`,
released 2026-09-23) — a promotion this project's own framing (that
document's "Why this promotion is not a routine version bump" section)
treats as adopting real upstream feature work, not a mechanical version
bump: a generalized gateway-provider contract (OneCLI restructured onto
it, Iron Proxy added as a second real gateway), multi-container/private-
network session isolation in the Go kernel, a provider-host-contract
mount-composition rewrite, multi-host claim/lease coordination, and the
community portal, among others.

The plan organized this work into two implementation PRs plus this
closing step, per its own "PR boundaries" section:

1. **Kernel capability** (Workstream A) — [PR #51](https://github.com/prathish-ks/isthmus/pull/51), `feat/mount-gateway-trust-class`, merged (`88263f7b`).
2. **TypeScript seam reconciliation and bypass closure** (Workstreams B, C) — [PR #52](https://github.com/prathish-ks/isthmus/pull/52), `feat/gateway-provider-seam`, merged (`81db8d9a`).
3. **This step**: the final, isolated pin-move — `docs/upstream-pin.json`, `docs/baseline.md`'s Stable Baseline section, this closing ADR, and the filled-in evidence index — no implementation changes, so that "is the pin move itself correct and fully gated" is reviewable on its own rather than buried in 196 files.

Workstreams D (full-diff inventory and reconciliation), E (testing), F
(documentation), G (CI uplift), H (migration continuity), and I (Design
Law closure) are the plan's own cross-cutting concerns spanning both
implementation PRs; their status is what this review confirms below.

## What this review confirms

Everything here was checked directly against the live state — the actual
GitHub check-runs API, the actual live upstream tag, the actual merged
PRs — not assumed from a document's own self-report, the same discipline
ADR-017 established.

**Both implementation PRs are merged with real CI evidence.** PR #51's
final commit (`8c47ec42`) and PR #52's final commit (`d85fef9b`) each
show their `ci` required-gate check run concluded `success` on GitHub
Actions, verified via `GET /repos/prathish-ks/isthmus/commits/<sha>/
check-runs` directly — including the new required
`go-multi-container-live-docker`/`live-egress-lockdown`/`coverage-gate`
jobs Workstream G added specifically for this promotion's own new
privileged surfaces, not merely the pre-existing `test`/`go-host` jobs.

**The tag is immutable and hasn't drifted since planning began.**
`v2.4.0` still resolves to `143db6c907c652773a536c7c9e96269fdad0a4a4` —
re-verified live (`GET /repos/nanocoai/nanoclaw/git/refs/tags/v2.4.0` →
tag object → target commit) immediately before this pin move, matching
the SHA `docs/promotion-v2.4.0.md` captured at Step 0 exactly.

**Every Workstream C finding closed outright — zero accepted exceptions.**
Three real trust-boundary findings (canonical-label precedence,
`approverUserId` persistence, OneCLI mount-path allowlisting), each fixed
with a negative-control-verified regression test, not merely noted. One
integration gap — the gateway-session lease's `release`/`onUnavailable`
lifecycle never actually wired into `container-runner.ts`, flagged by
this plan's own C1/C7 rows as a must-close item "the moment C8's Iron
Proxy needs them" — was caught independently during PR #52's own external
review cycle before merge (not after) and closed in that same PR
(`d85fef9b`): `ActiveSessionRuntime` now owns a real, tracked
`AbortController`, releases the lease on every terminal and pre-
registration-failure path, and subscribes `onUnavailable` to drive that
session's teardown.

**Migration continuity is real, not just designed.** `isthmus.sh` is the
current nanoclaw → Isthmus entry point (an in-place migration, not a
separate skill) — confirmed via a real dry run predating this promotion
(`docs/rollback-runbook.md`, 2026-09-06) and extended by two fresh
acceptance tests specifically for this promotion's source versions
(`docs/promotion-v2.4.0-rollback-v2.3.0.md`, `-v2.4.0.md`): both produced
byte-identical `data/v2.db` across migrate-and-rollback round trips, a
clean `nanogo doctor`, and a recorded rollback artifact each, with
matching outcomes between the two source versions (H4).

**The full-diff inventory (D0-D4) is complete and reviewable now.**
`docs/promotion-v2.4.0-file-inventory.csv` — 526 rows across `src/`,
`container/agent-runner/src/`, `setup/`, and `.claude/skills/` — has zero
unclassified rows and zero Bucket B (bypass-risk) rows without a
security-review status. This is the artifact that would have caught the
v2.3.0-era OneCLI skill/trunk move going unnoticed (the plan's own
motivating incident); it doesn't depend on CI and was reviewable before
either implementation PR opened.

**No architectural question was left open.** The plan's former "Open
questions / risks" section (renamed "Resolved questions and remaining
risks," 2026-09-27) is down to one live, non-blocking item — the
`channels`/`providers` sibling-branch base line moving once this pin
does, worth a cross-reference, not a promotion blocker. The three items
that used to sit there (the migration entry point, `container-runner.ts`
reconciliation, the wire-protocol version bump) are each resolved with a
pointer to where they were actually closed.

**One thing this review deliberately does not claim closed**: lease
continuity across a host restart. A graceful shutdown does not kill
running containers (`src/index.ts`'s `shutdown()` has no `killContainer`
call), so they survive for `adoptRunningSessions` to pick back up — but
adoption never calls `sessions.ensure()` again, so an adopted session's
in-memory gateway lease from the *previous* host process is simply gone,
with no release or re-establish call either way. This is a real,
separate, larger question about multi-host adoption and gateway-lease
continuity that this promotion's scope never covered and this review does
not resolve — tracked as a genuine follow-up, not glossed over as done.
Similarly, `poll-loop.ts`'s multi-turn reply-routing rewrite (bundled with
upstream's container-side provider-contract migration but deliberately
excluded from this promotion's C15 port) remains deferred with no forcing
function pulling it forward yet.

## Decision

**Promote the pin from v2.3.0 to v2.4.0.** `docs/upstream-pin.json` and
`docs/baseline.md`'s Stable Baseline section are updated in the same
commit as this ADR, per LAW-09's own discipline. Every line of `docs/
promotion-v2.4.0.md`'s Promotion Gate checklist is checked as of this
review; the checked-in version of that checklist, with each line's
evidence linked, is this pin move's own evidence index (below).

**Process decision, going forward, same as ADR-017's:** the automated
half (`upstream-watch`'s weekly job noticing a new tagged release exists)
stays automated; the qualitative half (reading what changed, deciding
whether it touches this project's ported surface) stays a human step,
triggered by that job's alert. The next promotion should follow this same
plan-then-implement-then-close shape — a living plan document, PRs scoped
to the plan's own boundaries, and a final, isolated pin-move PR — rather
than reinventing the process.

## Consequences

- `docs/upstream-pin.json`'s `review_doc` now points here, superseding
  `ADR-017-p9-07-upstream-overlap-review.md` as the current closing
  review.
- `go-host/docs/compatibility-matrix.md` and `go-host/docs/
  version-compatibility.md` are updated to describe `v2.4.0` as the
  current pin, not code "ahead of" it.
- Two real, named follow-ups carry forward, neither blocking this
  promotion: lease continuity across a host restart (Iron Proxy's
  in-memory lease is not re-established on adoption), and `poll-loop.ts`'s
  deferred reply-routing rewrite.
- The next phase that proposes new differentiated feature work should
  cite a review like this one, or ADR-017's, before assuming the current
  pin's contract shape is unchanged — matching the standing process this
  ADR and its predecessor both establish.
